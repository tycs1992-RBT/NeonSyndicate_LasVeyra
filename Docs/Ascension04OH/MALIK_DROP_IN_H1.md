# First production Malik candidate, drop-in checklist

Current status: no approved production Malik is present. The game uses its original, now refined, procedural skin. The calibration FBX is diagnostic and cannot become Malik through its proof. No purchase or unseen appearance approval is implied.

1. Obtain a lawful owner-approved skinned FBX, not an image or static OBJ. Retain Malik's established skin identity, undercut, beard and layered dark coat. Ask the supplier for a neutral bind pose, complete finger chains, clean skin weights, face/hair/eye/cloth/metal textures and equipment sockets. Keep original source and private rights receipts outside the public repository when required by their license.
2. Review an untrusted archive before Unity imports scripts or packages. The existing read-only intake tool inventories hashes and risky paths without extracting or executing it. Import only the approved model and required textures into an art candidate folder.
3. Open Neon Syndicate > 04OH > Imported visual proof wizard. Select the actual model. Use the bone and socket suggestions, then Audit. The current existing-pose adapter needs a complete mapping to the original 47 gameplay bones; extra passive visual bones can follow mapped parents. Unmapped required bones, invalid paths, bind/scale/skinning/material issues must be resolved, not suppressed.
4. Use positive, consistent scale, metre dimensions, a grounded pivot, +Y up and the established forward direction. Inspect handedness in the native model preview. The original controller, capsule, health, input, weapon motor and right-hand weapon contact remain outside the visual prefab. Imported colliders, scripts, lights, audio, legacy Animation and Animator controllers are rejected before cloning. Remove an Animator controller before audit; root motion remains disabled.
5. Record the real creator, asset/license ID, an opaque private rights-record ID, source and dependency hashes, lawful-use declarations and owner appearance decision. Missing rights remain pending. Create a DISABLED visual prefab and registry row. Do not enable it merely because an audit ran. The registry remains absent in this delivery because no candidate exists.
6. In the supported Editor inspect the candidate under Built-in first, then optional URP only if that pipeline is already configured. Verify actual skin, hair, eyes, normal direction, texture channels, cloth clipping and shader assignment. No renderer conversion or package installation is needed to follow the original pose system.
7. Verify idle, walk, sprint, turn, guard, attack, dodge, aim, fire, cast, the permanent blades, treatment attachments, vehicle grip, jump, flight and the earned regional art. Check hand sockets with the real equipped model. Exactly one original pose authority must remain. Supplied clips are inventoried; independent authored-clip playback/retargeting is SOURCE INCOMPLETE and cannot be enabled as a competing Animator.
8. Test invalid/missing candidate paths, component/controller rejection and disable/removal. The original fallback must return. Record actual results with Neon Syndicate > QA > 04OH Ascension Asset Acceptance before owner-approved activation. Review every changed source/dependency fingerprint again; an old audit cannot silently approve a changed model.

A detailed production head/skin/hair, realistic garment deformation, professional creature rigs and authored motion clips remain ASSET REQUIRED. This is a low-risk integration path, not proof that those assets have been supplied or natively accepted.
