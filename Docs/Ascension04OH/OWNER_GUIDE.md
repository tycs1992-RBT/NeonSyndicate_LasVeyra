# 04OH H0, Windows guide

This tests the real existing project and an inert diagnostic import. It does not install a professional Malik or a new renderer. No purchase or paid service is required for this diagnostic.

1. Close the Unity Editor. In GitHub Desktop click Fetch origin, select `feature/04oh-ascension-art-foundation`, then Pull origin. Fetch alone does not switch branches. You do not need to merge either draft PR to test a development branch. Preserve local changes.
2. Open the existing project using Unity 6000.3.16f1. Wait for import/compilation. If the Console shows errors, retain the first error and stack. Do not keep clicking Play through a compiler error.
3. Open `Neon Syndicate > QA > 04OH Ascension Asset Acceptance`. Start a new local evidence folder. This is the existing acceptance panel, with current SHA, actual renderer/world/bank, hardware and candidate context. A requested capture or test is not a passed result.
4. Click `Open original calibration fixture, NOT production Malik`, or use `Neon Syndicate > 04OH > Open original calibration fixture`. It selects the original Calibration47 FBX and suggests the real 47-bone map and visual locators. Inspect the model import, skin, units, bone paths and the CalibrationArmSweep clip in the normal asset inspector. The clip is diagnostic only. Do not count it as production locomotion or a paired art.
5. In the existing wizard click Audit. Save the audit text. A source/independent-parser pass does not guarantee Unity will import it correctly. Record actual missing bones, material, scaling, skin or importer errors. Do not apply arbitrary negative-scale or mirrored fixes just to hide a warning.
6. Keep diagnostic rows disabled. If you choose Create disabled visual prefab + registry row, it produces a separate local prefab with Animator and root motion disabled. Its diagnostic proof refuses runtime activation. It cannot become Malik by checking Enabled. Production model activation is a separate, approved workflow.
7. Stop Play Mode before running native EditMode/PlayMode tests. Use actual Test Framework callbacks and raw XML. LAUNCHED/RUNNING/interrupted/missing XML is not passed. No new native result exists until the test actually executes.
8. For the unchanged gameplay baseline choose Title > Living Frontier 04O-G, revision 6. Check the panel runtime line; do not load an older bank into this profile. Walk home, the original court/services, Dante's Forge, Archive, threshold/grotto and the existing regional paths with normal controls. Use legally earned boss/weapon/companion prerequisites, not debug rewards.
9. Capture actual day/night Game views at matching camera positions, gear, time/weather, renderer, seed and resolution. Save ordinary HUD-on combat and return/control behavior separately from staged Golden Views. Capture and profiling buttons require completed native output before the panel copies evidence.
10. Write the report and review the ZIP before sharing. Private receipts, raw paid art and player saves are not copied or uploaded by this workflow. The panel reports opaque asset IDs and hashes, not private rights documents. Record Windows build/launch separately after it actually runs.

## First production Malik candidate

No candidate has been approved or supplied in this delivery. Required: lawful source/export FBX, complete skin/bone map, face/hair/eye/clothing material and texture sets, equipment sockets, detail/LOD policy and actual compatible locomotion/combat clips. Preserve undercut/beard/layered-coat identity. Approval of the brief is not approval of an unseen model or a purchase budget.

Keep unreviewed vendor archives outside Assets. The worker's read-only `tools/inspect_art_drop_04oh.py` identifies files/scripts and hashes without extracting or executing them. Inspect licensing and scripts before Unity imports a package. A copied image, OBJ or renamed extension is not a skinned FBX. Restricted raw assets stay private, even when a commercial game-use license is valid.

For the actual approved Project model use `Neon Syndicate > 04OH > Imported visual proof wizard`. Record actual creator, asset/license IDs, an opaque private rights-record ID, lawful commercial use and owner appearance approval. New rows remain disabled; the original procedural visual stays authoritative. Source/dependency changes invalidate the enabled-row build audit. Legacy pre-04OH rows retain their original contract.

Only the existing-pose adapter is implemented. Detach any Animator controller from a candidate visual before audit/copy; controller state-machine behaviours cannot run beside the original pose owner. It disables Animator/root motion and follows original gameplay poses. Available AnimationClips are inventoried, not automatically played or retargeted. The authored-clip authority is explicitly SOURCE INCOMPLETE and refuses activation; it needs its own implementation and native tests after a real rig/clip set is available.
