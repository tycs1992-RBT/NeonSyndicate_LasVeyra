# Owner guide: supplied character and creature art

ASSET REQUIRED. No lawful rigged FBX, material/texture set or authored animation was supplied or imported in this delivery. The procedural game remains the normal fallback. This is a visual adapter workflow, not an asset marketplace or arbitrary-animation retargeter.

1. Use a model/texture/animation license that permits use and distribution in your game. Keep the license and provenance beside art. Use `Assets/NeonSyndicate/Art/Imported/malik/Models` (and sibling Textures, Materials, Animations and Prefabs folders). Keep generated .meta GUIDs and existing FBX/texture LFS rules. Do not replace canonical gameplay prefabs or import a second controller/damage/save package.
2. In the existing Unity 6000.3.16f1 project, select the model in Project. Configure a valid rig/Avatar in its ordinary Inspector if supplied. Choose compatible Built-in materials, or explicit compatible URP materials when testing that optional renderer. Assign base color, normal, metallic/smoothness and selective emission textures in normal material Inspector. Roughness inversion, skin/eye/hair authoring and material conversion are not automatic here. Keep original files.
3. Open Neon Syndicate > 04OF > Imported visual wizard (also linked from the acceptance panel). Assign the Project model/prefab in its object field. Use identity malik, npc:Dante Rook, creature:veilglass_castellan, creature:stormroot_sovereign, or `companion:<original archetype>`. Do not invent an ownership ID.
4. Use detailed human template for Malik/detailed NPCs. For a biped boss, nonhuman or owned drake, run the actual game, select the live actor and read its original rig. Stop Play Mode before writing art. An owned drake requires a positive legitimate UID. The window keeps original bone order, including actual humanoid fingers; a biped creature can have only 17 bones.
5. Suggest Avatar/name bone matches. A genuine Humanoid importer mapping is used when available; unique exact names are a fallback. Review EVERY original source bone and assign actual target Transform or relative path. No empty, duplicated, escaping path or out-of-range source. Extra weighted twist/accessory bones must descend from a mapped target and are explicitly recorded as passive. Root-only model layouts may require a separate visual wrapper root. Forward axis, proportions, left/right orientation, rest/skin deformation and bone length compatibility need native inspection.
6. Assign visual head/chest/fx/synergy locators; humanoids also need hand_r, hand_l, foregrip, muzzle, blade_hilt and blade_tip. The body-point suggestion is approximate and does not replace original weapon locators. Precision muzzle/tip/foregrip remain on the real equipped weapon. Native smoke test must compare real hand and blade contact; a locator name is not proof of alignment.
7. Audit. It reports mesh/bind-pose count, missing mappings/weighted ancestry, scale/bounds, supported shaders/normal map presence, Avatar, clips and LOD groups. No collider, rigidbody or gameplay script is allowed. Review clip/LOD/root/face warnings. It inventories clips; it does not play an imported animation controller. Original procedural pose wins. Facial retargeting and arbitrary-rig adaptation remain unfinished.
8. Create a separate visual prefab and disabled registry row. Choose its asset path. The existing registry is Assets/NeonSyndicate/Resources/ImportedModels04OD.asset. No duplicate canonical row is overwritten. New row stays Enabled false; a newly created registry stays disabled. Manually enable BOTH registry and row only on a disposable native test setup after all checks. No invented prefab reference is committed by this sprint.
9. Enter Play Mode, select actual Malik/actor and use Neon Syndicate > 04OD > Smoke test selected visual fallback. Attach/request only, not a passed test. Inspect normal camera, front/side, idle/run/turn/dodge, gun/muzzle, both blades, coats, casting, facial channels, scene/cutscene/Pause, hit/death/ragdoll, flight, vehicles and companion hide/unhide/down. Disable the row and start again to compare procedural fallback. Saving always belongs to original systems; do not overwrite protected saves for art testing.
10. Save the audit text, then use the acceptance panel for actual screenshots/logs. If validation fails, keep the procedural renderer, inspect the error and fix the supplied visual copy. Do not disable safety checks to force an incompatible model to show.

No native import, skin deformation, shader/LOD behavior, supplied animation quality or performance is accepted until you run and review it. The wizard is source/API verified but has not been clicked on the Work host.
