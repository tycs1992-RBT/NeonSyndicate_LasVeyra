# Owner walkthrough: prepare, visit the Forge, identify the buildings

This is a review procedure. The first gate is Unity import and preparation on your actual computer. Nothing here certifies the world, interactions or visual result.

1. Before changing the running session, press **F2 > Fantasy proof** and capture the branch/build stamp, player position, FR01 and FR02A preparation and first-refusal rows, and World Rewrite rows. Open **Window > General > Console**, select the `Physics.ClosestPoint` warning and copy its full stack trace and the action that produced it. Save the first red error separately. The single warning line in the screenshot is not enough to identify its owner.
2. Save normally. Back up the entire game's existing save folder, including `.bak` and temporary files, to a separate folder. Unity's `Application.persistentDataPath` is the source; on a standard Windows Editor installation this is normally `%USERPROFILE%\AppData\LocalLow\Neon Syndicate\Neon Syndicate Las Veyra`. Revision 10 files have the prefix `lasveyra_civic_h5_save_`. Do not overwrite or migrate any other bank. In GitHub Desktop select `feature/04oh-ascension-art-foundation`, **Fetch origin** and **Pull origin**, preserving local changes.
3. Stop Play after preserving progress. Open this project in **Unity 6000.3.16f1** and wait for import and compilation. Choose **Neon Syndicate > Acceptance > Verify Fantasy World**, then click **1. Verify preparation and source identity**. Opening the window alone does not run preparation. Success means the current commit is shown and there are no preparation blockers; it is not gameplay acceptance. If it fails, copy the exact first blocker and the first Console error, including the asset path and full stack when present.
4. Resume your existing safe Free Roam save. In **Pause > EXPLORE**, choose **PLAY FANTASY WORLD** if the ordinary session allows it. Take another F2 proof capture. FR01 and FR02A each report their own state; a failure in one layer does not establish the state of every other layer. If selection or preparation fails, keep the existing presentation and report the first refusal.
5. Walk from home toward the Archive and Forge using the normal camera. At the Forge's actual entrance, look at the existing floor and the three inner walls: the candidate is intended to show a lighter stone path toward the anvil and framed wall bays. The real anvil and Dante remain where the existing game put them. Try the normal Dante and anvil interactions only when legitimately available. Also check the Archive entrance, lectern and its existing interaction. Record what is actually reachable. Toggle preview OFF and ON using the existing controls and compare the same viewpoint; the original surfaces should return when OFF.
6. Continue on foot toward the stone threshold, mineral grotto and woodland approach, then return. The EXPLORE route markers can help, but an active mission retains priority. Follow the existing journal and requirements. `Where the Trees Ring` requires `Stone, Not Silence`; do not grant either quest or any reward to stage the test.
7. At each reported giant building record a nearby landmark and F2 position. Capture a normal ground-level view and, if flight has already been earned, a short continuous flight alongside the walls and over the roof. State whether a wall stopped Malik or whether a roof supported landing. Also capture the same area with the preview OFF. If practical, select the visible object in the Unity hierarchy and record its renderer and collider names separately. Do not use a teleport to establish route access.
8. Keep any failed preparation, inaccessible route, misleading doorway, fly-through wall or unsupported roof as a failed check. Send the F2 rows, first error and warning stack, plus the two building clips or views. Do not treat a prepared label or object count as proof of visual quality.

The window's separate native-review button can back up saves but starts a separate review flow. It is not required for this walkthrough; manual backup and the existing save avoid relying on a fresh session. To undo the new look during review, leave Fantasy World preview or use the existing comparison OFF control. For a source rollback, use a separate checkout of the parent or a normal revert of the published change; never reset shared history or replace your saves.
