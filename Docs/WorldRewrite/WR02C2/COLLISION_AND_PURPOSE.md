## Collision plan, still subject to owner authorization

1. Capture the actual checkout, player position, selected object and hierarchy for each of the two walls. Identify the renderer and the original collider owner separately. Record local/world bounds, active layer, material, LOD and whether the object is a service, replacement or background. Do not change the shared city chunk or unrelated services.
2. With the existing player and ordinary camera, document contacts at ground, doorway, all exposed wall faces, roof/ledge and from earned flight at ordinary and fast approach speeds. Compare visual surfaces against the exact active original colliders and show where contact diverges. Check the scene before and after loading/streaming and turning the preview off.
3. First consider reshaping or disabling only the isolated candidate to fit existing physical surfaces. Preserve the original visual on refusal. If the original collider is already approved for that same owner, investigate a narrowly scoped repair against the exact mismatch; it needs native verification. Never close a real doorway or present an unsupported roof as a landing surface.
4. If new physical geometry is needed, prepare a specific owner-linked proposal with dimensions, portal/room clearances, layers, visual fit, activation and restoration; seek the owner's explicit authorization before adding it. Do not turn on the EscarpmentArch or create speculative box walls now.
5. Before acceptance, test on-foot movement and camera, all doors/floors/interactions, NPCs and companion paths, vehicles where applicable, flight in both directions, roof landings, view obstruction, preview disable, streaming, quit/reload and existing saves. Run the existing regression checks; retain actual Game View/flight evidence and the owner's decision.
