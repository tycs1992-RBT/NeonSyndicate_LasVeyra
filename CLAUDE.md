# Neon Syndicate: Las Veyra (rules for AI coding sessions)

Unity 6000.3.16f1 (Unity 6.3) open-world action game. **Everything is generated by C# at runtime**: the city, people,
creatures, vehicles, weapons, sounds, music, textures and UI. There are no art or audio assets.
`Assets/NeonSyndicate/Resources` holds only four shaders (two for the Built-in pipeline, two for the URP beta) and the
quest and world event JSON. The owner, Tyler, is not a programmer and builds by directing AI: explain changes in plain
words, and never claim something works in Unity unless it was run in Unity.

## House rules (strict)

- **No em-dash or en-dash characters anywhere**: code, comments, strings, docs, commit messages. Use commas, periods,
  parentheses or the word "to".
- **No names of other commercial games, their studios, characters, places, brands, songs or commercial asset products**
  in any project file. All names in the game are invented. Describe a purchased tool generically ("a creature
  animation pack"). One exception (owner decision 2026-10-24): a credit a license requires, such as a CC-BY creator
  credit in an art folder's `CREDITS.txt`, names the creator exactly as the license asks, even when a username contains
  such a name.
- **Never break the twelve compile configurations**: editor and Windows player, each with the classic Input Manager,
  with both input systems and with the Input System only, once on Built-in and once with the URP package installed.
  Input System code goes inside `#if ENABLE_INPUT_SYSTEM && NS_INPUT_SYSTEM`, URP-only code inside `#if NS_URP` (both
  defines come from the asmdef versionDefines).
- **Every new static gets a `ResetStatics()`** that is called from `Game.ResetStatics()` (Core/Game.cs), so Enter Play
  Mode without domain reload starts clean.
- **Controller parity**: every new player input works on keyboard and mouse and on a gamepad (see Input below), and the
  key table in `Docs/CONTROLS.md` is updated with it.
- **Save data is append-only**: `SaveData` (Gameplay/SaveSystem.cs) is JSON through JsonUtility. Only add fields, with
  a sensible initializer for old saves. Never rename, retype or remove a field; the `SaveDataTests` freeze list fails if
  you do (add your new field to that list).
- **Content is data**: quests, contracts and world events are JSON in `Resources/Quests` and `Resources/Events`, never
  a C# class per quest. Every file must pass `QuestValidator`, and a shipped id is never renamed (saves remember it).
- **Keep files focused**: prefer a new file (or a `partial` class file) over growing a big one. Match the style: XML doc
  summaries in plain English, explicit types (no `var`), C# 9, Unity 6 APIs, `Log.Info/Warn/Error/Exception` for logging.
- **Test pure logic offline**: anything that can be plain math goes in an engine-free class and gets an EditMode test.
- Systems must degrade gracefully: callers null-check `Game.X`, boot steps are wrapped so one failure cannot stop the game.

## Architecture

- **Boot**: `GameRoot` creates itself after any scene loads (`RuntimeInitializeOnLoadMethod`, AfterSceneLoad), so every
  scene works. `Awake`: settings, graphics, physics layers, `PlayerCamera.Create()`. The `Boot` coroutine then runs, in
  order: audio clips, `new CityLayout(Game.Seed).Generate()`, map texture, `CityBuilder.Build`, traffic signals, street
  lights, breakable props, `Atmosphere`, Inner World, effects, explosions, radio, stats, economy, GPS, wanted, police,
  traffic, pedestrians, pickups, collectibles, abilities, combat, progression, mythic gear, materials, bestiary, skill
  trees, factions, Forge, loot armory, travel powers, missions, activities, world services, creatures, quests, world
  events, cheats, minimap, HUD, menus, phone, then the title screen. Each system is a component under "Systems", created with `AddSystem<T>` inside
  `Step(...)` so an exception is listed on screen instead of freezing the boot.
- **Registry**: `Game` (Core/Game.cs) holds every live system as a static field (`Game.Atmo`, `Game.Player`,
  `Game.Cam`, `Game.Hud`, `Game.Layout`, ..., and the Phase 3 and 4 fields below), plus `Game.State` and `Game.Seed` (61724,
  the default city).
- **ResetStatics**: `GameRoot` calls `Game.ResetStatics()` at SubsystemRegistration; it nulls the registry and calls
  each static class's `ResetStatics()`. Every static class's ResetStatics must be called from Game.ResetStatics().
- **Procedural everything**: materials via `Shader.Find` (Built-in Standard and friends, URP Lit on the beta path) in
  `Mats`, textures in `Tex`, meshes with `MeshBuilder` and `Shapes`, sounds in `AudioSynth`, songs in `MusicSynth`,
  creature voices in `CreatureSounds`. The editor setup keeps the needed shader variants in builds (`EnsureShaderKeep`).
- **Pure-math solvers**: `CityLayout`, `Appearance`, `RigLayout`, `BodyBuilder` (one skinned mesh per person, built on
  worker threads by `BodyFactory`), `HumanoidPose` (IK gait, attacks, dodges, weapon holds, travel and riding poses),
  `WeaponGrip` table, `CreatureBuilder` and `CreaturePose`, `CreatureLogic`, `AudioSynth`, `WeaponInventory`,
  `MeleeMoves`, `PostGrade`, `UrpGradeMapping`, `QuestLogic`, `QuestValidator`, `QuestJson`, `EventSelector`,
  `FactionRules`, `ForgeMath`, `SkillBook`, `LootGenerator` and `LootRules`, `TravelMath`, `BikeMath`, `PerfPath`,
  `GoldenViews`.
  Keep them engine-free: use `Mathf`, `Vector3` and `QMath`, not `Quaternion.Euler/LookRotation`, `Debug`, `Time`,
  `Physics` or `JsonUtility` (those call native Unity and fail offline).
- **UI**: immediate-mode IMGUI. `UIKit` scales to a 1080p reference (`UIKit.BeginScaled`) and draws text, bars and
  panels; `Hud` (partials `HudCombat`, `HudZones`), `MenuSystem` (title, pause, map, shops, F2 debug menu), `Phone`,
  `ForgeScreen` (pauses like a shop). Phase 3 pages plug in through the hooks below: pause tabs SKILLS, JOURNAL,
  FACTIONS, BESTIARY (`SkillsPage`, `QuestBook.Ui`, `FactionsPage`, `BestiaryPage`) and Phase 4's ARSENAL
  (`LootArmory.Ui`), and F2 tabs Creatures, Quests, Events, Progress, Loot, Travel. `Game.Hud.Hidden` hides the HUD (F3).
- **Input**: `Keys` (key map, mirrored in `Docs/CONTROLS.md`), `GInput` (keyboard and mouse through the classic Input
  Manager or the Input System, whichever is active; `GInput.GameplayBlocked` while menus own input), `Pad` (gamepads
  through the Input System 1.17.0 package: taps, holds, chords, rumble, button names per pad family) and `Act`
  (gameplay actions that merge keyboard and pad). New gameplay input goes into `Act`. A Third Eye tap (decided on
  release) is bullet time; holding it 0.7 s shifts through the Veil instead. Dialogue: Enter or A shows the next line,
  Backspace or B skips the rest of the conversation or the whole scene.
- **Time**: `GameTime` owns `Time.timeScale` (slow-motion requests by key, pause wins). `Atmosphere.SetTime(hours)`
  and `SetWeather(w, instant)` drive sun, sky, fog and lights; one game hour is two real minutes.
- **Saves and settings**: `SaveSystem` writes `lasveyra_save_<slot>.json` (0 autosave, 1 to 3 slots) in
  `Application.persistentDataPath`; Phase 3 systems write their own blocks through `IWorldSystem` (below); `Settings`
  uses PlayerPrefs with the `NSLV_` prefix.
- **Render paths**: Built-in Render Pipeline is the default (`NeonPost` on the camera, `OnRenderImage`: bloom, AO,
  motion blur, eye adaptation, ACES grade, FXAA). The opt-in URP beta (`Docs/URP_MIGRATION.md`) is chosen by
  `RenderPath.IsURP`: `MatsUrp` maps the procedural materials to URP shaders, `NeonUrpPost` fills a runtime Volume from
  the same grade numbers through `UrpGradeMapping`, `NeonPostFeature` (Render Graph) adds eye adaptation and the exact
  vignette, `UrpGraphics` maps the graphics presets. Menus: Neon Syndicate > Graphics > Switch to URP (beta), Switch
  back to Built-in, Render pipeline status (the switch writes its assets to `Assets/NeonSyndicate/Rendering`). Both
  paths read the shared colour grade from `Core/PostGrade.cs` (`PostGrade.Compute` plus the `InnerWorld`, `Frost` and
  `Rift` weights); change grading there, never in one pipeline only.
- **Camera**: `PlayerCamera` (foot, vehicle, first person, ragdoll, title flyover). `SetCinematic(pos, look, fov)`
  and `ClearCinematic()` take it over for cutscenes and QA captures.
- **Editor setup**: `NeonSyndicateSetup` runs on every editor load: input handling (an old-Input-Manager-only setting
  becomes "Both"), layer names, fog variants, shader-keep materials, the game scene first in the build list. Menu:
  Neon Syndicate (Play, Build Game for Windows, Repair Project Setup, saves, Graphics, QA).

  and GameRoot's new-game reset and load walk the list, each call wrapped so one failure is logged and the rest still
  run. A new system appends one block field to `SaveData` (and to the freeze list) and touches neither SaveSystem nor
  GameRoot. Today's blocks: Creatures, Materials, Factions, Quests, Events, Crafting, Skills, Loot, Travel.
- **MenuPages**: `MenuPages.Register(new MenuPage { Title, Order, Draw, Visible })` adds a pause tab (Order below 100
  sits after GEAR, 100 and up after SAVE / LOAD). Today: ARSENAL 5, SKILLS 10, JOURNAL 20, FACTIONS 25, BESTIARY 30.
- **DebugPages**: the same for the F2 debug menu, after its built-in tabs. Today: Creatures 20, Quests 30, Events 31,
  Progress 40, Loot 45, Travel 46.
- **HudOverlays**: `HudOverlays.Register(key, (w, h) => ...)` draws on the gameplay HUD in UIKit scaled space; an
  overlay that throws is logged and removed. Today: creature bars and wind-up warnings, bestiary toasts, the quest
  tracker, event callouts, reputation toasts, brew timers, and in Phase 4 the loot pickup card, energy heat bar and
  champion name plates, and the travel power panel.
- **Data-driven quests and events**: JSON in `Resources/Quests` (givers, quests, contract templates) and

- **Per-system docs**: `Docs/CREATURES.md`, `Docs/QUESTS_AND_EVENTS.md` (file format, step types, how to add a quest),

## Phase 4 systems (loot, travel powers, hover bikes, animation)

- **Loot guns** (`Game.Loot`, LootArmory with partials Drops, Ui, Hud, Shop, Debug; `LootGenerator` and `LootRules` are
  pure): procedural guns (8 types, 6 invented makers, 7 parts, Common to Mythic, 4 elements, 15 traits, named uniques)
  rebuilt exactly from a seed record (`LootGunSave`). Four equipped slots are the WeaponIds `Loot1` to `Loot4`
  (`Weapons.LootSlots`), so the inventory, wheel, HUD and saves treat them like any weapon; `Weapons.Get` returns the
  live definition for a slot. Drops scale with the enemy tier (normal, Shard-Touched elite, champion, boss) and
  difficulty, with a pity rule. Champions (`NpcController.Champion.cs`) carry affixes and a weapon core. Weapon cores
  are materials; the Forge's ARMORY tab infuses, ascends, raises the level and scraps. Meshes: `LootGunModels`. NPCs
  never carry loot guns. Details: `Docs/LOOT.md`.
- **Travel powers** (`Game.Travel`, TravelPowers; `TravelMath` is pure; movement in `PlayerController.Travel.cs`,
  camera in `PlayerCamera.Travel.cs`): Surge (super speed), Super Leap and Glide, Flight. They set
  `HumanoidAnimator.Travel`, `TravelBlend` and `TravelLean` (x pitch, z positive banks right); the pose solver draws
  them. Unlocks follow story progress (Surge from the start, Leap and Glide after mission 1, Flight after mission 2,
  everything in Free Roam). Details: `Docs/TRAVEL.md`.
- **Hover bikes** (`VehicleClass.Bike`, `BodyStyle.Bike`, `Vehicle.Bike.cs`, `BikeModels`, `BikeMath`, `BikeSpots`,
  `PlayerController.Bike.cs`): riders sit in view at the `RideAnchors` (Seat, HandleL, HandleR, FootL, FootR) of
  `HumanoidAnimator.RideRoot`; the rider's root stays upright and the animator applies `RideLean`. The prologue gives a
  bike at the start; the title screen has Start After the Prologue; Phone > Bring my bike. Details: `Docs/VEHICLES.md`.
- **Animation** (`HumanoidPose` with partials Weapons, Travel, Ride; `WeaponGrip` with its pure table): gait from
  published human kinematics (tested by `GaitTests`), two-handed weapon holds by IK (the support hand goes to the
  model's `Foregrip` child, which every two-handed model carries), travel and riding poses. `HandPose.Apply` is called
  every frame with a grip per hand but is still a stub: finger bones are planned for the character visuals pass.
  Details: `Docs/ANIMATION.md`.
- **Offline character harness**: `/home/claude/tests/CharTest` builds bodies and poses with the real code;
  `--gait` prints joint angles, stride and foot sliding per speed against human reference ranges.

## Build and test

Close the Unity editor for this project before running these (Unity cannot open one project twice). Logs and test
results go to `Logs/`. Full steps for Tyler are in `Docs/TOOLING.md`.

```
powershell -ExecutionPolicy Bypass -File tools\build.ps1            # Windows build -> Builds\Windows\NeonSyndicate.exe
powershell -ExecutionPolicy Bypass -File tools\build.ps1 -Target Mac
powershell -ExecutionPolicy Bypass -File tools\test.ps1             # EditMode tests, exit 0 = all passed
tools/build.sh                                                      # macOS build -> Builds/Mac/NeonSyndicate.app
tools/test.sh [--filter SaveDataTests]
```

The scripts find Unity in Unity Hub's folder for the version in `ProjectSettings/ProjectVersion.txt`, or take
`-UnityPath` / `--unity` or the `UNITY_EXE` environment variable. Underneath:
`Unity -batchmode -quit -projectPath <p> -buildTarget StandaloneWindows64 -executeMethod NeonSyndicate.EditorTools.BuildScripts.BuildWindows64 -logFile <log>`
(`BuildMacOS` with `StandaloneOSX`; add `-nsDevelopment` for a development build), and
`Unity -runTests -batchmode -projectPath <p> -testPlatform EditMode -testResults <xml> -logFile <log>` (never `-quit`
with `-runTests`). Inside the editor: Window > General > Test Runner.

Tests live in `Assets/NeonSyndicate/Tests/EditMode` (city layout, bodies, pose solver, save data, colour grade, weapon
and melee tables, QA maths, creature logic, progression, quest data, quest logic, quest saves, world event selection).
Add tests next to them for new pure logic. Mark tests that need the engine itself (for example JsonUtility) with
`[Category("NeedsEngine")]`.

## QA capture tools (Play mode)

Menu Neon Syndicate > QA, or from code `QaTools.StartGoldenShots()`, `QaTools.StartPerfCapture()`, `QaTools.Busy`,
`QaTools.Cancel()`, `QaTools.LastMessage`, `QaTools.LastOutput`. From the title screen they start Free Roam first; Esc
cancels; the camera, clock, weather, HUD and player are restored afterwards. They refuse to start during a mission or
while wanted; a menu or the phone opened mid-capture pauses golden shots (the shot is retaken) and stops the perf run.

- **Golden shots**: 14 fixed views (`GoldenViews`) at 12:00 and 22:00 (28 images), clear weather, HUD hidden, film
  grain off, the player parked in the desert, saved to `<persistentDataPath>/GoldenShots/<yyyyMMdd_HHmm>/` with
  `manifest.json`. A capture always starts outside the Veil. The first 12 views keep their names and order (old sets
  still compare); `frostline_outpost` and `veil_core_street` were appended, the second taken inside the Veil (the
  capture shifts in and back out instantly, with the Veil's drain paused). Append new views at the end, never reorder.
- **Compare Golden Shots**: picks two folders and writes `report.html` (before, after, heatmap), `report.md` and
  `report.json` into `GoldenShots/Compare_<before>_vs_<after>/`.
- **Perf flythrough**: about 80 s along `PerfPath` at 21:00, frame-rate cap lifted, writes `Perf/<timestamp>.csv`
  (frame, CPU main, render thread, GPU where reported, GC bytes per frame) and a `.txt` summary (avg, p50, p95, p99,
  max, worst 10 frames with where they happened).

## What an AI cannot verify (ask Tyler)

This repository is often edited where there is no Unity editor or GPU. Compiling and offline tests prove the code
builds and the maths is right; they do not show how it looks, feels or runs. Visuals (lighting, materials, post
effects, animation feel), game feel (camera, controls, combat timing), frame rate and anything that needs real input
must be checked by Tyler in Unity. Say so plainly in your summary and tell him exactly what to look at. Phase 3 has not
been run in Unity yet; its first-session checklist is in `Docs/STATUS_AND_TESTING.md`.

**Golden screenshot loop** for any graphics, lighting, shader, post or render-pipeline change:
1. Before the change, Tyler runs Neon Syndicate > QA > Capture Golden Shots (same Game view resolution every time,
   for example 1920x1080).
2. Make the change.
3. Tyler captures again, runs Compare Golden Shots and sends the report (or the big-change images) back.
4. Judge the heatmaps and numbers against the intent; anything "big" that was not intended is a regression.
For performance work, run the Perf flythrough before and after and compare the .txt summaries.
